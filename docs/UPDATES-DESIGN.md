# 更新及 CI 准备记录

这是 M2 后已授权里程碑的设计准备，尚未添加 GitHub 工作流、更新安装入口、签名私钥、Tag、Release 或线上部署。真实 SMTP 投递和线上 Workers 配额为外部验证待办，不能用这些未授权线上试验无限阻挡其余可验证的本机实现。

## 已只读研究的机制

2026-10-03 阅读了用户指定旧项目的相关源码与开发约定；没有执行其发布脚本、访问其凭据或修改旧项目。此处记录可复用的机制，不复制未经核对许可的实现或个人配置。

| 来源 | 实际读到的机制 | Harmonia 采用或补足的边界 |
| --- | --- | --- |
| password-manager-switch、xiaomi-backscreen-switch | main/PR 检查、独立 v* Tag 发布、数字 beta/rc 的预发布标记；Gradle 的 versionCode 与 workflow run_number 联动 | 后续可复用检查与发布阶段分离。run_number 只在单 workflow/repo 内递增，迁仓/重建工作流可能回退；Android 需独立保存可核验单调构建序号，不能直接照抄基数加 run_number |
| ledger-lens | 三 OS 检查；darwin/linux/windows 各 amd64/arm64 六目标构建并验证 GOOS/GOARCH/CGO 标记 | 普通 CLI/daemon 六目标与原生 SPAKE2 依赖分别验证；交叉编译不算 OS 服务验收 |
| codex_tweaks | stable 排除 draft/prerelease；beta 包含 beta/rc 与 stable，按语义版本排序；跳过版本、并发检查互斥、错误保留；原生包更新由平台机制负责 | 不根据 API 列表首项、发布时间或资产后缀猜最新可信版本；只有明确匹配目标的已签包可安装，失败不能显示已是最新 |
| smartsearch | 自动检查24小时节流、已安装版本与缓存远端信息分开、缓存不直接获得更新资格；包管理器 ownership 与确切目标验证；合成包签名/引用/重复资产负例 | 服务更新另有特权边界，不继承任意包管理器命令或宿主敏感 env；签名验证与实际健康检查都通过才完成 |

Action/tool 版本仅为读到的旧实现事实。实际添加工作流时再核对官方资料与当前可用版本、固定引用；未把旧注释版本当当前推荐。

## 用户可见检查行为

- daemon 启动延迟检查，此后每24小时加随机抖动；CLI只读缓存，提示写stderr，不污染JSON。
- 手机只在前台检查，24小时节流；不增加后台常驻更新服务。可关闭自动检查，默认stable，beta需主动选择。
- 同版本提示一次，可稍后或跳过。手动检查仍有最低间隔；网络、签名、元数据和限流错误分别表示，失败退避。
- 产品版本与协议major分离；共同major和操作capability均满足才同步/写入。无共同major给升级提示，不能降级已依赖新来源的保护状态。重复恢复的明确major提案见 [协议DAG合同](https://github.com/harmonia-vault/protocol/blob/main/docs/RECOVERY-DAG.md)，实现前仍为提案。

## 安装与信任边界

更新来源和验签公钥独立于账号、设备及恢复钥。生产签名材料尚未建立，不读取任何旧项目私钥；测试使用临时合成材料。未获得有效发行签名时拒绝安装。

签名承诺完整产品版本、渠道、目标OS/架构、协议major集合、包长度、SHA256及下载来源；客户端严格解析、限制大小、匹配自身目标、拒绝回退/混用渠道或未知字段。元数据验签和完整包验签/摘要验证均在替换前完成。SHA256校验单独不能证明发行者。

CLI主动升级和服务helper升级使用同一互斥及固定路径策略：受保护暂存→验证→停服→替换→健康检查→成功清理；失败恢复原受保护程序和服务状态。不得接收任意命令、任意路径、调用者自给验签公钥或继承vault秘密。健康检查不能以读取真实凭据作为测试。

Android提示完整签名APK下载，安装交由系统；未来iOS使用商店。未生成/上传发行签名钥或发布安装包，因此当前仅是待实现合同。

## 后续验证与工作流范围

先验证缓存/节流/并发/语义版本/错误行为，再用临时合成包验证错误签名、目标错配、并发升级、替换故障、健康失败和回滚。所有安装试验在临时目录或隔离VM，不修改宿主真实安装。

后续CI首先运行五仓库的协议互操作、业务与安全测试、受支持跨平台构建，以及workspace固定submodule联合验收。普通构建和原生依赖使用明确矩阵，检查源码/依赖版本和子模块漂移。原生VM/Android证据、线上配额和真实邮件投递各保持独立状态，不以工作流文件存在或编译完成代替验证。

本阶段不触发发行工作流；正式Tag/Release、安装包和真实线上部署仍须另行授权。当前M2进度及公开固定测试见 [STATUS.md](STATUS.md)。
