# 分层测试预算

本规则依据用户于 2026-10-04 确认的测试分层，适用于固定产品清单中的所有功能。清单描述用户可用行为，不要求每一种业务组合在 Android 和 iOS 各重跑一遍。

| 层次 | 必要验证 |
| --- | --- |
| 共享 Go/Dart 业务 | 优先级、角色、期限、状态转换、参数、原 ID 重试与去重用单元测试覆盖一次；改动后只复验直接受影响项 |
| 客户端与服务器 | 使用真实 HTTPS/业务接口及本地持久化集成验证权限、幂等、序号、原子状态和接受后下发；不依赖 UI 覆盖每种组合 |
| Android/iOS 原生 | 各保留一条最短完整主流程；定向验证系统认证、Keychain/Keystore、前后台、进程终止和恢复等平台差异 |

已发现的实际认证、隐私遮罩、密钥存储或生命周期问题仍须原生复验，mock 不能替代。编译证明 ABI 和类型兼容，不能冒充认证或真机通过；模拟器结果不冒充物理设备硬件验证。

相关源码与依赖没有变化时，复用已有 PASS；不为新文档、接线或其它平台改动重跑旧业务矩阵。每次只运行主流程、直接回归和真实安全边界。多角色、多期限、多重试状态的 UI 组合后置，不能成为重复覆盖共享业务的默认要求。Linux P5 已按分段实际证据完成，不因测试分层调整重新打开。

PASS、FAIL、UNRUN 和中断后无法确认的 UNKNOWN/UNCONFIRMED 分别保留。工具调用丢失回执时先查原意图、结果文件和进程，不重复不确定的外部动作。网络不稳定时先完成不依赖实时 GUI 的源码、单测和接口工作。

测试分层不改变产品权限、原生认证、到期、撤销或原 ID 约束，也不自动完成尚未实现的功能。未验证的能力保持明确限定，项目仍为实验性安全软件。
