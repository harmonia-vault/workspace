# 执行计划

1. **M0 盘点与基线**：相关工作规范和 memory_summary（不读 sessions）、GitHub 身份/组织权限、工具/VM；保存完整设计；秘密/个人数据检查后立即初始化并公开 MIT 五仓库。
2. **M1 首个可测试纵向切片**：确定性协议/向量；成熟 AEAD、签名、HPKE；本机合并、override、逐 key 恢复、到期清理和 CLI；服务端账号持久化、序号、幂等与当前授权；合成端到端测试。生产路径不得提供无证明的设备信任绕过。
3. **M2 配对与账号生命周期**：成熟 SPAKE2、手机审批/管理签授权、HTTPS 登录/Argon2id、独立注册/验证开关、发信验证/重置、多账号隔离和检查点。尚未实现的控制默认拒绝。
4. **M3 恢复与轮换**：种子分用途派生/恢复封套、受限恢复会话、绑定单次挑战、完整重输新码、原子钥匙/封套切换、账号 generation 重置、结果不明查询。
5. **M4 本机系统集成**：按用户开机服务、原子 shell fragment、Windows 用户 registry、显式勾选导入、暂停/撤销/退出、崩溃幂等收敛；隔离 VM 账号验证，不污染宿主。
6. **M5 移动与运行时验收**：验证订阅/真实参数后按实际需要及用量动态使用 Claude Opus 5.5 medium 编写 UI；Flutter+Go、Android 钥匙保护/CRUD/审批/恢复和模拟器；保留 iOS 兼容并如实报告未跑检查。Node SQLite 重启与 Workers D1/DO/Argon2 运行时本地实测，不部署。
7. **审查交付**：刷新 submodule 固定提交、秘密/个人数据复查，推送经过测试的源码和证据，报告路径、链接、通过/失败/未跑以及所有未完成安全门槛。

持续按可测试里程碑推进，不在脚手架结束。目标涉及多轮持续实现；每个已验证结果保存提交，设计目标不能冒充实现结果。所有项目说明文档使用中文。

## M2 后的已授权更新与 CI/CD 里程碑

先完成当前 M2 的安全与核心端到端实现及验证，再实现自动更新和 CI/CD。未验证结果不得提前写成已完成。正式 Tag、Release、安装包发布和真实线上部署仍不包含在本阶段授权内；发布签名私钥生成/上传须批准或用户安全输入，不读取旧私钥。

1. daemon 启动后延迟检查更新，其后每 24 小时加随机抖动；CLI 只读缓存提示到 stderr，不污染 JSON。手机前台检查有 24 小时节流，无后台常驻更新 daemon。同版本提示一次，可稍后或跳过；手动检查仍受限流约束。失败退避，不把失败说成“已是最新”；默认 stable、beta 主动选择，可关闭自动检查。
2. 产品版本与协议 major 分离，破坏性协议变更提升 major。端点协商支持的 major 集合，有交集才继续同步；无交集拒绝远端同步/写入并给升级提示。兼容扩展按 capabilities 协商。
3. CLI 主动升级与服务 helper 升级需互斥、签名验证、停服、健康检查和失败回滚；Android 提示完整签名 APK 下载，未来 iOS 使用商店。更新源与验签公钥独立，测试失败、缓存、并发、回滚和渠道，不让测试读取真实签名材料。
4. 先实际读取相关旧项目源码：password-manager-switch、xiaomi-backscreen-switch 的数字预发布/main PR 检查/v* Tag；ledger-lens 的 Go 六目标；codex_tweaks、smartsearch 的 stable/beta feed 与签名测试。只复用已理解机制，记录 Android run_number versionCode 跨仓迁移风险。
5. CI/CD 检查五仓库及 submodule 固定版本，验证协议/业务/安全测试、跨平台构建和更新签名边界。先保存可审查实现并如实报告运行结果，不以工作流存在冒充成功发布。
