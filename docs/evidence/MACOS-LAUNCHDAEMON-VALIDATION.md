本次使用从零创建的官方 ARM64 macOS 测试虚拟机与独立合成账号。未使用宿主真实环境变量、凭据或旧虚拟机账号；未打开 SSH、共享目录、共享剪贴板、额外安全权限。结果只能证明本次已执行路径，不表示生产可用。

## 安装与测试边界

公开材料为 12 个正常文件，传输仅监听宿主 VM 私网接口，只允许本次来宾地址获取固定归档。第二版归档 SHA256 为 `0219e075fd0a5d0f7c95cafe40bf27abd3b3312a47edc3396079a47ec290633f`，21353835 字节；来宾实际 SHA256 与冻结值一致后解压，安装脚本再次检查逐文件摘要并拒绝所有已有目的路径。

正式 LaunchDaemon 的程序和 plist 属于 root，`UserName` 明确指向目标普通用户。只有公 CA 通过 `--ca-file` 指定给本 CLI；未安装系统根证书，也未跳过证书链或主机名验证。受保护资料使用普通用户的独立 0700 末级目录，机器软件钥使用 0600 文件，启动不依赖登录后解锁的 Keychain；这不构成硬件钥匙保护声明。

测试管理控制器与目标 CLI 使用不同的受保护目录。合成密码在来宾内随机生成，经匿名 stdin 交给正式 CLI；配对短码经匿名 stdout pipe 交给成熟 Go 管理流程，不显示在终端、不发给业务服务器、不记录日志。首次初始化必须完整重输恢复码，配对执行正式 V3 SPAKE2、设备签名、管理批准及原申请完成回执。任何首次尝试残留都拒绝重新初始化，不覆盖已有管理材料。

临时 HTTPS 服务采用正式 VaultService 和 SQLite。审计只记录请求方法、路径、状态与接收时间，禁止记录 Authorization、请求体、密码或密文内容。TLS 私钥只留宿主私有临时目录。临时 root 观测器只上报 boot UUID、控制台 UID、服务 PID/UID 和有限状态，不读保险库、钥匙或变量值；它不授予账号权限。

## 保留的失败与修正

1. 第一次公开字符输入使用 `flagsChanged`，大小写和符号不符合预期，记 FAIL。后来采用官方 SDK 定义的物理左 Shift 标志与普通 KeyDown/Up，实际公开 `Aa0_1:2` 精确匹配；八进制冒号拼接也通过。未启用共享或改变系统权限。
2. 初版安装脚本因人工将平台 UUID 中 `E` 误读为 `F`，严格 guard 在任何目录创建和注册前退出，记 FAIL。第二版根据实际 guard 诊断修正固定常量，保留原归档，使用新的来宾临时路径，正常安装通过。
3. 启动动作测试脚本误把 BSD `stat -f %a` 当作权限格式，实际是访问时间；guard 退出前没有启动服务，随后 CLI 收敛检查失败，均记 FAIL。仅本任务脚本改为 `%Lp`，保留原副本，来宾修改后的 SHA256 精确匹配冻结值 `f14238b8e695847847d44a740d6af239e9898e932885439fe16402640d7ff0fa` 后启动和 CLI 通过。
4. 观测器要求 scutil 的名称字面等于 `loginwindow`；当前启动时该条件未匹配，原字段与原始文件保持不变。登录后的只读解析诊断可解释差异，但不能倒推旧启动时的名称；不得静默扩大旧条件。

## 尚未覆盖

此记录不等同于手机系统认证、真实 Mac 硬件防护、FileVault 未解锁启动、GUI/容器/cron 环境适配或所有 shell 生命周期验收。宿主环境未被托管。Mac 本地 sh/bash/zsh 的长期交互纠正和逐 key 恢复应独立实测；Linux 已有结果不能替代 Mac 证据。

重启后的普通系统登录发生在预登录证据冻结之后。登录后的只读 scutil 返回合成目标账号名称、UID 501；它不能解释或覆盖原启动时的名称。暂停撤销的正式服务器接受发生在临时 HTTPS 期限内；随后清理执行本地正式退出流程，不依赖已结束的 HTTPS 服务。

清理保留了新测试 VM 与合成系统账号，没有修改宿主环境或删除旧 VM。来宾只移除本任务两个 LaunchDaemon、程序目录、两份 plist、受保护资料及刚下载的公开归档。宿主仅关闭本任务的临时服务与公开传输端口，并删除刚生成的合成 TLS 私钥和空实例测试数据库；公开公证书、固定源码、摘要与无秘密元数据保留。

## 正式 macOS 安装仍缺的产品部分

本次固定提交中的 `platform.LaunchDaemon` 已支持用户名、非 root UID、程序路径、状态路径、轮询间隔与显式 CA 文件；每 UID 的 label、`UserName`、`RunAtLoad`、`KeepAlive` 和 `Umask` 都已存在。`service-templates/generate.go` 仍使用合成固定参数，只输出待审查文件；它不是安装器。本次临时脚本完成了安装工作，但含单次 VM 守卫和测试路径，不能直接作为用户安装入口。

| 部分 | 已有机制 | 产品安装缺口 |
| --- | --- | --- |
| 参数化与冲突处理 | 可测试的 ServiceConfig 和按 UID 命名配置 | 正式入口应从实际目标账号解析并交叉核对 UID/GID；提供明确路径和 CA 参数；区分新装、已有受控安装与冲突，不能直接复用本次固定 UUID 或覆盖未知文件。 |
| 权限与生命周期 | 本次 root-owned 程序/plist、目标用户 0700 状态目录已实测 | 安装器需核实际文件及所有祖先、符号链接、ACL、文件类型与所有权，原子安装；使用正常提权运行有限系统动作；启动失败不得丢失既有资料，升级和卸载需明确处理与恢复规则。配置生成器的字符串路径规范化不能替代真实文件系统检查。 |
| 用户隔离 | 正式 daemon 以目标普通 UID 运行，CLI 和 Unix 受保护存储验证本地身份 | 正式安装入口需把账户、状态目录、服务 label 与 IPC 端点作为同一范围验证，并覆盖第二 UID 拒绝和多用户并存；本次只实测一个新 UID，不能借此宣称所有多用户安装情况通过。 |
| 开机凭据与 shell 接入 | 0600 软件机器钥、受保护设备材料、每次持钥 boot challenge/session；重启不依赖登录 Keychain | 首次配对应以目标 UID 在正式服务目录建立资料，不迁移宿主凭据或以账号登录代替设备信任；生产安装应明确软件钥与磁盘解锁权衡。sh/bash/zsh 的用户确认接入、交互纠正和卸载逐 key 恢复仍需 Mac 独立测试。 |
